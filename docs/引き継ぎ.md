デプロイ順は **API → アプリ → サイト**。逆にするとアプリが未実装の受け口を呼び、
`404 見つかりません` になる（2026-08-24 に実際に起きた）。
`GET /health` が `{"ok":true,"version":"..."}` を返すので、**どれが動いているかは version で確かめる**。
受け口を足したら `API_VERSION` も更新すること。
**注意**: 鍵なしの要求はパスに関係なく 401 を返す（認証がルーティングより前）。
`/me` が401だから新しい版が出ている、とは言えない。判定は version で行う。

画面構成: **アカウント（任意で作る）→ その中に預ける・取り戻す**。
設定にはアカウントを開く入口だけ置く。ユーザー名（20文字まで・表示専用）は
`users.display_name`。パスワードは作らない（OTPのみ）。API は `GET/POST /me`。
実測（2026-08-24・ローカル）: API通し試験28/28成功。ブラウザで
ログイン→預ける→**pool/dataを空にして再読込**→取り戻す、で
問題5問・4グループ・学習記録（メモ・ブックマーク・正答数）が復活することを確認。
取り戻しは**足すだけ**（置き換えは作らない）。API先は `VITE_API_BASE`（既定 `https://api.quiz-make.com`）。
開発時は `.env.development.local` に書く（`.env.local` にすると本番ビルドにも効くので使わない）。

### ローカル検証手順
`api/.dev.vars`（gitignore済み）に4行を置く。`--var` は値を数値として渡すことがあり、
`DEV_ECHO_OTP` が効かない事故があったため、ファイルで渡すほうが確実。
```
SECRET_PEPPER=testpepper
RESEND_API_KEY=dummy
DEV_ECHO_OTP=1
OTP_BURST_SECONDS=0
```
```
cd api
npx wrangler d1 execute quizmake --local --file=schema.sql
npx wrangler d1 execute quizmake --local --file=migrations/0001_add_display_name.sql
npx wrangler dev --local --port 8790
API_BASE=http://127.0.0.1:8790 node test/flow.mjs   （36項目）
```
アプリと一緒に動かすときは、リポジトリ直下に `.env.development.local` を置いて
`VITE_API_BASE=http://127.0.0.1:8790` と書き、`npm run dev`（5173はCORS許可済み）。
`DEV_ECHO_OTP=1` のとき、6桁が入力欄に自動で入る。
**注意**: 通し試験を続けて2回流すと、IP上限（30回/時）に当たって失敗する。
`DELETE FROM rate_limits;` をローカルDBに流してから再試行する。
**注意**: `wrangler.jsonc` に routes を入れたため、dev でも Host は `api.quiz-make.com` になる。
そのため OTP の開発用エコーは**ホスト名ではなく `cf-connecting-ip` の有無**で判定している
（本番の要求には必ず付く／ローカルの dev には付かない）。
**注意**: wrangler dev が終了しても `workerd.exe` がポートを掴んだまま残ることがある。
つながらないときは別ポートにするか、残った workerd を終了させる。
**注意**: dev稼働中にローカルD1へ外から書くとサーバーが落ちる。試験はAPI経由のみ。
compatibility_date は `2026-08-18`（それより新しいとworkerdが起動しない）

## 非交渉ルール（SPEC.cc.md にも記載）
- `window.confirm/prompt` 禁止 → ConfirmDialog/PromptDialog
- main の子（各View root）に **min-width:0**（無いとページごと横に伸びる）
- 折り返しは body の **overflow-wrap: anywhere** 1か所（break-wordでは最小幅が縮まない）
- 色は `--c-*` のみ。ハードコード禁止。虫食いの保存色は `inkColor()` で読み替え
- 学習記録のキーは**問題文**。編集時は `study.moveRecord` で引っ越す（放置すると記録が消える）
- 削除は `removeQuestion/removeGroup` の2経路のみ → ごみ箱を通る。新しい削除口を作らない
- **保存失敗は必ず画面に出す**（pool.saveError と study.saveError の両方）
