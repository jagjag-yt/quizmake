## 1. 配布の前にやること（ここが最優先）

連絡網で配るということは、**受け取る人があなたを知っている**ということです。
つまずいたときに問い合わせが直接あなたに来ますし、うまく動かなければ
それはあなたの評判になります。配る前に、次の3つを済ませておくのが安全です。

### ① 実機のスマホで一度通す

パソコンでは確認済みですが、実際に配る相手の多くはスマホで開きます。
**あなたの本物のデータ量**で、次を一度ずつ通してください。

1. 過去問まとめを読み込む → 問題数が想定どおりか
2. 演習を10問ほど解く → 記録が残るか
3. アカウント → 預ける → 一覧に今日の日付と問題数が出るか

> スマホ（600px以下）では問題作成は案内画面になります。
> 配る相手が「作る」側なら、その説明を一言添えてください。

### ② 受け取った人が最初に開くページを決める

いま `/guide`（使い方）は公開されていますが、**トップページからのリンクがありません**。
連絡網で配るなら、送るURLは次のどちらかに絞るのが親切です。

- 解いてもらうだけ → `https://app.quiz-make.com` を直接
- 作り方も知ってほしい → `https://quiz-make.com/guide` を先に

トップからガイドへの導線を足すかどうかは、既存ページを触る判断になります。
**配るURLを固定するなら、必ずしも足さなくてよい**というのが私の見立てです。

### ③ 配布物に短い説明を添える

過去問まとめのファイルと一緒に、3行だけ添えてください。

```
・URLを開くだけで使えます（インストール不要・無料）
・データはあなたの端末に保存されます。消えると困る人は
  アカウントを作って「預ける」を押すと、7日分をサーバーに預けられます
・うまくいかないときは support@quiz-make.com か、私に直接
```

**「預ける」を必ず案内してください。** 6aを作った理由がここにあります。

## 2. 配った直後にやること

### 使われ方を見る（1〜2週間）

Cloudflare Web Analytics が動いています。見るのは3つだけで十分です。

| 見るもの | 判断すること |
| --- | --- |
| 訪問者数 | 配った人数のうち、実際に開いたのは何割か |
| ページ別 | `/guide` が読まれているか（読まれていないなら説明が足りている） |
| 再訪 | 2回目以降があるか。**ここが本当の合格ライン** |

> 1回開いて終わりなら、機能ではなく**中身（問題）と使い始めの摩擦**の問題です。
> 機能を足す前に、そこを聞き取ったほうが早く効きます。

### 問い合わせに備える

来る質問はだいたい次の3つです。先に答えを用意しておくと楽になります。

- 「別の端末で開いたら問題が無い」→ 預ける・取り戻すの説明
- 「Excelが読み込めない」→ 列の形式（`docs/動画台本.md` の準備物が参考になります）
- 「消してしまった」→ ごみ箱、または預けたものから取り戻す

### 段階4（動画）は、ここで効く

## 3. 利用者が増えたら（50人 → 200人）

### 段階5：X での宣伝

連絡網で配る分には不要ですが、**連絡網の外へ広げたくなったとき**の手段です。
`docs/Xアカウント準備.md` のとおり、凍結明けの初動だけ守ってください
（1日10フォロー以内・同じ文面を繰り返さない・リンクなしの投稿を混ぜる）。

急ぐ理由はありません。**最初の50人の反応を見てからで遅くない**と考えます。

### 段階6b：自動双方向同期（有料の予定）

いまは「押したときだけ預ける・取り戻す」です。6bは**自動で両方向に合流させる**もので、
本体は「2つの端末で別々に編集したとき、どちらを残すか」という難問です。

- 作る量は6aと同じくらい、難しさは段違い
- 事故（データ喪失）の防止には**6aで足りている**
- 有料機能にする決定は済んでいますが、**課金の仕組み（段階8）が先に要ります**

> 私の推奨は変わりません。**「2台以上で使っていて、手動が面倒だ」という声が実際に出てから**
> 着手するのが順当です。声が無いうちに作ると、いちばん難しいものが一番使われないことになります。

### 段階7：広告（200人超が目安）

- プライバシーポリシーの改定が**必須**（広告配信事業者による情報の取得が生じるため。
  現在の第8項に予告済み）
- 学習中の画面に出すと集中を切ります。**出すなら一覧や結果の画面**に絞るのが穏当です
- 200人未満では収益がほぼ出ません。手間と評判のほうが先に減ります

## 4. 課金を始めるとき（段階8）に必要なこと

月300円／買切1000円という値付けは決まっていますが、**技術以外の準備**がまとまって必要です。
ここは早めに知っておくと慌てません。

| 必要なもの | 中身 |
| --- | --- |
| 決済の仕組み | Stripe など。手数料（3.6%前後）とアカウント審査が要る |
| **特定商取引法に基づく表記** | 有料で売る場合は**掲載義務**があります。氏名・住所・連絡先・価格・支払時期・返品の条件など。個人だと住所の記載が問題になりやすいので、事前に確認が必要です |
| 返金の方針 | 買切1000円で「思っていたのと違う」が来たときの答えを決めておく |
| 規約の改定 | 有料機能・支払・解約の条項。現在の利用規約には課金の条項がありません |
| 消費税の扱い | 価格が税込か税別か。少額なら課税事業者かどうかも関わる |
| 無料で残すもの | **6a（預ける・取り戻す）は無料のまま**が決定事項です。事故を防ぐ機能を有料にすると、失った人が「払っていれば」と感じ、評判に直結します |

> 有料にすべきは**費用がかかるもの**（画像の保存など）だと整理してあります。
> 同期そのものを有料にする場合も、6a と 6b の線引きを利用者が説明できる形にしてください。

## 5. 技術的な積み残し（急がないが、忘れると痛い）

| 項目 | いまの状態 | いつ効いてくるか |
| --- | --- | --- |
| `SECRET_PEPPER` の控え | 投入済み。**変えると全利用者がログアウト** | 端末を替えたとき・再設定したとき |
| 障害に気づく仕組み | Workers の observability は有効。ただし**通知は無い** | 利用者が増えて「動かない」と言われて初めて気づく形 |
| バックアップの実効性 | ローカルで28項目の通し試験。本番では手動確認1回 | 半年後に「戻せない」が最悪。定期的に1回通すとよい |
| D1 の残量 | 5GB 無料枠。1人5MBで200人＝1GB | 画像を扱い始めたら一気に変わる |
| Resend の通数 | 3,000通/月。ログイン1回＝1通 | 200人が月1回ログインしても余裕あり |
| 学習記録のキーが問題文 | 編集時は `study.moveRecord` で引っ越す設計 | 問題文を大きく書き換える利用者が出たとき |
| 学習記録（Dashboard）の要否 | 実利用を見てから判断、としてある | 使われていなければ削るほうが画面が軽くなる |

## 6. 私からの推奨（優先順に3つだけ）

1. **配る前にスマホで一度通す。** 作ったものが手元で動くことと、相手の端末で動くことは別です
2. **配布物に「預ける」の一文を必ず入れる。** 6aを作った意味がここで回収されます
3. **配ったあと2週間は、機能を足さない。** 何に困るかを聞いてから決めるほうが、
   作る量あたりの効果がはるかに大きくなります

段階6b・7・8は、いずれも**利用者の数か声が条件**です。
いま着手する理由は無く、条件が満たされてからで間に合います。
