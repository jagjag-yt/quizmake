## 1. 全体像

```
無料（アカウント任意）        有料（買切・アカウント必須）
─────────────────────      ─────────────────────
問題の作成・演習・虫食い       同じ機能ぜんぶ
書き出し・読み込み            ＋ 広告が消える
預ける・取り戻す（7日分）      ＋ 自動同期（6b）
広告あり                      ＋ 将来：画像の保存
```

**機能は原則すべて無料**にし、有料で買うのは「**広告を消す**」と「**手間を減らす（自動同期）**」の
2つにします。機能そのものを人質にすると、無料の人の体験が悪くなり、
配った同級生の中に「使えない人」を作ることになります。

## 2. 価格と方式

### 推奨：買切 1,000円のみ（サブスクは作らない）

| 方式 | 良い点 | 悪い点 | 判断 |
| --- | --- | --- | --- |
| **買切 1,000円** | 一度きりで分かりやすい。解約の導線・督促・自動更新の説明義務が要らない | 継続収入にならない | **推奨** |
| 月300円 | 積み上がる | 学生には重い。解約対応・特定商取引法の継続課金要件・失敗した決済の督促まで作ることになる | 見送り |
| 両方 | 選べる | 作る量が倍。同じ機能に2つの値段があると説明が要る | 見送り |

**理由**：いまの規模（50人）で継続課金の仕組みを作ると、**作業量の大半が課金の管理**に消えます。
買切なら「払った人の印を1つ持つ」だけで済みます。
サーバー費用は現在0円で、有料の人が増えても当面は0円のままです（Workers・D1の無料枠）。
**費用が増えるのは画像を保存し始めたとき**なので、そのときに月額を検討すれば足ります。

### 収益の見込み（正直な数字）

| 前提 | 数 |
| --- | --- |
| 利用者 | 50人 |
| 有料に移る割合 | 2〜5%（無料で困らない作りなので低め） |
| 買う人 | **1〜3人** |
| 収益 | **1,000〜3,000円**（手数料 3.6% を引いて 964〜2,892円） |

広告（月100〜400円）と合わせても、**当面は月あたり数百円**です。
金額よりも「**仕組みを作って回しておく**」ことが目的だと考えてください。

## 3. 決済

### 使うもの：Stripe

- 手数料 **3.6%前後**（1,000円で36円）
- 振込は口座へ。個人でも開設できる
- **Stripe Checkout**（Stripe が用意する決済ページ）を使えば、カード番号は
  こちらのサイトを一切通りません。安全で、作る量も少なくて済みます

### 決済手段の選び方（学生が相手であることを踏まえて）

| 手段 | 備考 |
| --- | --- |
| クレジットカード | 本人名義を持っていない学生が一定数います |
| **Apple Pay / Google Pay** | スマホで完結。家族のカードを登録している人が多く、実際にはこれが主力になります |
| **コンビニ決済** | Stripe で有効化できます。カードを持たない人の逃げ道。入金確認まで時間差があるので、**入金後に有効化**する作りが必要 |

> **推奨**：カード＋Apple Pay／Google Pay で始め、「買えない」という声が出たらコンビニ決済を足す。

## 4. 「払った」をどう覚えるか（技術）

いまのアカウント（`users`）に**印を1つ足すだけ**です。

```sql
ALTER TABLE users ADD COLUMN plan TEXT;          -- 'paid' のみ。無料は NULL
ALTER TABLE users ADD COLUMN paid_at TEXT;       -- 支払い日時（ISO8601）
ALTER TABLE users ADD COLUMN payment_ref TEXT;   -- Stripe の支払いID（問い合わせ照合用）
```

流れは次のとおりです。

1. アプリの「アカウント」画面に［広告を消す（1,000円）］を置く
2. 押すと Stripe Checkout へ飛ぶ（メールアドレスは渡す。カード情報はこちらを通らない）
3. 支払いが成立すると、Stripe から **Webhook** が `api.quiz-make.com/stripe/webhook` に届く
4. 署名を検証し、そのメールアドレスの `plan` を `paid` にする
5. アプリは `/me` の応答に含まれる `plan` を見て、広告を消し、自動同期を解禁する

**重要な性質**：買切はアカウントに紐づきます。つまり
**有料にする人はアカウントが必須**です（無料の人は今までどおり任意）。
機種変更しても、ログインし直せば戻ります。この「買い直しにならない」ことは
購入前に画面で明示します。

**やらないこと**：端末に鍵を保存して判定する方式。コピーで簡単に破られ、
かつ機種変更で消えます。サーバーで持つほうが、利用者にとっても安全です。

## 5. 法務・事務（ここが技術より重い）

有料で売ると、**掲載義務**と**税**が発生します。始めると決めた時点で確認してください。

| 項目 | 中身 | 私の見立て |
| --- | --- | --- |
| **特定商取引法に基づく表記** | 販売者名（氏名）・住所・電話番号・価格・支払時期・引渡時期・返品条件などの掲載義務 | **最大の障害**。個人だと自宅住所と電話番号を公開することになります。「請求があったら遅滞なく開示」で足りるとする運用もありますが、**判断は専門家に確認してください**。バーチャルオフィスを借りる手もあります（年1万円前後） |
| 返品・返金の方針 | デジタルなので原則返金不可、と書くのが一般的。ただし**二重課金や不具合のときは返す**と明記する | 「買ったのに広告が消えない」は必ず起きます。窓口（support@）を書いておく |
| 規約の改定 | 有料機能・支払い・返金・アカウント必須・未成年の同意 | 現在の利用規約に課金の条項はありません |
| プライバシーの改定 | 決済事業者（Stripe）へメールアドレス等が渡ること | 第5項に追記 |
| 消費税 | 年間の売上が1,000万円以下なら免税事業者。インボイス登録は、相手が学生（控除不要）なら**不要** | いまの規模では登録しないでよい |
| 未成年 | 高校生以下が買う場合は保護者の同意が要る | 規約に一文。同級生（大学生）が中心なら実務上の影響は小さい |

> **住所の公開が難しい場合、有料化そのものを止める判断もあり得ます。**
> その場合は広告のみで進め、課金は保留にできます。ここは先に決めてください。

## 6. 6b：自動同期（有料の目玉）

### いまとの違い

| | 6a（無料・実装済み） | 6b（有料） |
| --- | --- | --- |
| きっかけ | 利用者が「預ける」を押したとき | **自動**（開いたとき・変更のあと） |
| 向き | 預ける／取り戻すの一方通行 | **双方向** |
| 難所 | なし | **2つの端末で別々に編集したとき、どちらを残すか** |

### 設計（推奨する形）

**問題1つずつを単位にして合流させます。** 文章全体を新しい方で上書きすると、
片方の端末の編集がまるごと消えます。

- 問題・グループに `updatedAt`（更新時刻）を持たせる（すでに一部にある）
- 同期のとき、**同じ id は新しい `updatedAt` を採用**する
- 片方にしか無いものは足す
- 削除は「消えた」ではなく**ごみ箱に入った印**として送る（消したのか、まだ届いていないのか区別するため）
- 学習記録は**問題ごとに合算**する（解いた回数は多い方、最終解答日は新しい方）

### 安全策（前回の事故を繰り返さないため）

- **同期の前に必ずスナップショットを取る**（6a の「預ける」を自動で1回）。
  合流に失敗しても、日付を選んで戻せる状態を保ちます
- 最初の実装は**手動の「いま同期する」ボタン付き**にし、自動は後から有効にします
- 通し試験に「2台で別々に編集 → 同期 → 両方の編集が残る」を必ず入れます

### かかる量

**私の作業で4〜6日**（6a と同じくらいか、やや多い）。難しさは段違いです。
サーバー側の差分API、クライアントの変更追跡、競合の解決、そして試験が要ります。

## 7-2. アプリ側の広告（2026-09-02 実装ずみ・利用者の指示）

**枠は作った。ID を入れるまで1つも出ない。** 出す場所は3つ。

| 場所 | 形 | 環境変数 |
| --- | --- | --- |
| 結果画面の下 | バナー | `VITE_AD_SLOT_RESULT` |
| グループ一覧の下 | バナー | `VITE_AD_SLOT_GROUPS` |
| 演習を始める手前 | 1枚（スキップできる） | `VITE_AD_SLOT_START` |

**決めごと（非交渉）**

- **演習中の画面には広告を出さない。** 選択肢のそばに広告を置くのは規約違反にあたるうえ、
  考えている途中で邪魔をすると学習が続かない。
- **演習前の1枚は「重ねない」。** ポップアップの中の広告は AdSense が認めていない。
  本文と入れ替える1枚の画面として描く（`AdInterstitial`）。
- **いつでもすぐ閉じられること。** 右上［スキップ ✕］・下［▶ 演習をはじめる］・Esc のどれでも進む。
  秒読みで閉じさせない。開いた瞬間［スキップ］にフォーカスを置く。
- **押すたびには出さない。** 既定で20分に1回（`ADS.START_COOLDOWN_MIN`）。
  続けて解く人ほど邪魔になるため。0 にすると毎回出る。
- 未設定のときは枠ごと描かない（空の箱や「広告」の字だけが残らないように）。

**利用者にやってもらうこと（審査に通ったあと）**

1. Cloudflare の `quizmake` プロジェクトのビルド設定に環境変数を入れる。
   `VITE_AD_CLIENT`（ca-pub-…）と、上の表の3つの広告ユニットID。
2. `public/ads.txt` と `site/public/ads.txt` に発行者IDの行が入っていること
   （2026-09-02 に記入ずみ： `google.com, pub-6422017157291772, DIRECT, f08c47fec0942fa0`）。
   **アプリとホームページの両方に要る。** 無いほうのドメインの配信が止まる。

   > **ads.txt には日本語を書かないこと。** この2つのファイルは文字コードの指定なしで
   > 配信されるため、日本語のコメントはブラウザで文字化けする（2026-09-02 に実際に起きた）。
   > 判定に使う行は ASCII なので配信自体は動くが、見た目が壊れていると
   > 「設定を間違えた」と勘違いする。説明はこの文書に書き、ファイルは ASCII だけにする。
3. 新しいコミットを main に流してビルドを起こす（環境変数だけ変えても再ビルドは走らない）。

> **住所について。** 広告だけなら、住所を**公開する必要はない**。AdSense に出す住所は
> 支払いと本人確認のためのもので、サイトに載るものではない（PIN の郵送先になる）。
> 住所の掲載が要るのは**特商法**＝有料プランを売るときで、広告とは別の話。
> 自宅を公開したくないなら、広告だけ先に進めて有料化は保留にできる（第8節の2）。

## 8. 決めてほしいこと

1. **価格と方式**：買切1,000円のみ（推奨）でよいか
2. **特商法の住所**：自宅を出せるか、バーチャルオフィスを借りるか、**有料化を保留するか**
3. **返金の方針**：原則不可＋不具合と二重課金は返す、でよいか
4. **決済手段**：カード＋Apple/Google Pay で始めてよいか（コンビニは後から）
5. **6b の解禁範囲**：有料のみでよいか（無料は6aのまま）
6. **有料の名前**：画面に何と出すか（例：「広告なしプラン」「サポータープラン」）

> 1・3・4・5・6 は今日決められます。**2だけは調べる必要があります。**
> 2が固まらないうちは、1〜4（広告側）だけ進めるのが安全です。
